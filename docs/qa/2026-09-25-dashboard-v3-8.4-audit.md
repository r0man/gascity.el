## 1. Render guard over every view

`gascity-test-audit-render-guard-every-view` opens each entry of
`gascity-audit-views` by its real command on a remote city
(`/mock::/home/roman/emacs-city/`, context memo primed = first contact
done), serves every read from `lisp/test/fixtures/v3`, then TABs to
every thing, SPC-toggles each, runs `g`, and evaluates the header line —
inside `gascity-test-with-render-guard`.

Views: cockpit, Agents table, Agents tree, agent detail, Runs, run
detail, Health, Cities, rig dashboard, rig/session/convoy/mail/order/
Dolt lists, costs, the log follower. Events and Mail are entries marked
`:pending`, skipped until `gascity-events` / `gascity-mail` are
commands (comms).

Also asserted: every read had a fixture (the views rendered data, not
error lines), every non-text view had things to walk, and no file
primitive was called on a host-only name (`/method:host:`) at all.  On
d56da64 the walk saw 154 such calls, all `file-remote-p "/mock:m1:"`
from `gascity-store--pump`; after the store fix (4b78993) it sees none,
and the test now allows none.

| `gascity-cities` / `--host-dir` | `(expand-file-name "~")` from a remote buffer dispatches to TRAMP through `default-directory` | expand against `/` (`gascity-cities--local-home`) |

## 4. File primitives reachable from timers, sentinels, filters

`gascity-test-audit-callback-file-io-reviewed` scans every
`gascity-*.el`: callbacks handed to `run-at-time`/`run-with-timer`/
`run-with-idle-timer`, `set-process-sentinel`/`-filter` and the
`:filter`/`:sentinel` of `make-process`/`make-pipe-process`, following
gascity calls 7 deep, for `file-remote-p`, `expand-file-name`,
`abbreviate-file-name`, `file-exists-p`, `file-directory-p`,
`project-current`, `locate-dominating-file`.  Every (callee . primitive)
pair must be in `gascity-audit--reviewed-callback-io` with a reason; a
new one fails.  `abbreviate-file-name`, `file-exists-p` and
`project-current` are reachable from no callback.

Manual review of the call sites on main 4cf1b96 (the reviewed list is
exact — a pair that disappears must be dropped too):

| Callee | Primitive | Verdict |
|---|---|---|
| live `--classify`, `--start`, `-command`, `--spawn`, `--ssh-p` | `file-remote-p` | stream root, full dir: pure |
| reader `--command`, `-read-async`, `--read-async-ssh`, `--remote-dir-absent-p` | `file-remote-p` | `default-directory`, full dir: pure |
| remote `-flush-file-cache`, `-spawn-error-hint` | `file-remote-p` | full dir: pure |
| context `-city-root` | `expand-file-name`, `locate-dominating-file` | memoized; a timer hits the memo of a pinned root — after `gascity-context-clear-cache` the next tick walks synchronously (bounded) |
| reader `--remote-dir-absent-bounded-p` | `file-directory-p` | reached from the live poll timer (non-ssh methods): bounded but synchronous |

On d56da64 the list also held the store scheduler's host-name calls
(`gascity-remote-connection-locked-p`, `-prewarm`, `-ssh-transport-p`);
4b78993 replaced them with the pure `gascity-remote-prefix`.

## Findings for other owners (not changed here)

1. **store**: `gascity-store--pump` handed the host name to
   `file-remote-p` — fixed in 4b78993; the audit now allows no
   host-only call (`gascity-audit--host-only-reported` is empty).
2. **live**: the poll timer (`gascity-live--poll`, non-ssh methods)
   calls `gascity-reader-read-async` directly, outside the store, so
   the reader's synchronous directory probe (`file-directory-p`,
   bounded) runs on every poll tick; through the store a known-good
   directory skips it.
3. **live/context**: `gascity-live--root` (timer paths) calls
   `gascity-context-city-root`; after `gascity-context-clear-cache` the
   next tick walks the remote tree synchronously (bounded).
4. **terminal**: tmux attach runs tmux synchronously (session-exists
   probe, `set-option status off`, remote TERM probe, executable
   resolution) via `process-file` — over TRAMP for a remote city — and
   the status mirror's timer (`gascity-terminal--status-refresh`,
   every `gascity-terminal-status-interval` s) keeps doing so.  Exempt
   in the D9 guard with this reason.
