## Method

is wrapped in `timeout(1)`, tmux sessions are verified before every
`send-keys`/`capture-pane`, and point positions are read with bounded
`emacsclient` evals. The worktree's own `lisp/` is on the load path (so the
pass exercises the branch, not the launcher checkout), dependencies via
`EMACSLOADPATH` as `Makefile.am` sets it.

### Defect found in review and fixed on this branch

While reviewing the chained branch, the inspector's events line was read from
the store's `:lines t` payload as a plain list; that payload is
`(GOOD . BAD)`, so the drawer always said `(no recent events)`. Commit
`d525a42` (originally `57f8108` on the `ga-ti6ah` branch) reads the car and
pins the shape with an end-to-end drawer test. After the fix, C above shows
real events live. Recorded here because it changes inspector behaviour the
earlier stages' summaries describe.

## H. Deviations and follow-ups

1. **`I` on a drain-member row says `No step here`.** The `└ ⬣ ga-4618o
   do-work … RET run` rows are real member runs, but
   `gascity-run--step-at-point` does not know them, so the inspector (and `w`,
   `!`) cannot open there; `RET` drills into the member run instead. Filed as
   `ga-miqt3` (P3), not fixed in this stage.
2. **`v` target resolution** — see E; `ga-rdxf6` (P2, affects all views).
3. **`!` lands on the failed anchor**, not the innermost failed iteration —
   matches the implementation and its tests; documented above rather than
   treated as a bug.
4. **Events line-mode fix** (`d525a42`) is included on this branch; without it
   the inspector's events line is always empty.
5. `gc events --follow` keeps one child process per attached city (the live
   stream); opening and closing the run buffers did not leave extra streams
   behind.
