## Method

`scripts/e2e-harness.sh` discipline throughout: every emacs/tmux call is
bounded by `timeout(1)`, the tmux session is verified before captures, and
elisp polling loops carry hard iteration caps. A fresh non-graphical Emacs
runs inside tmux, at 200x60, with the **integration worktree's** `lisp/` on
the load path (dependencies via `EMACSLOADPATH` as `Makefile.am` sets them):

```sh
tmux new-session -d -s gce-rv3 -x 200 -y 60 \
  "cd /home/roman/emacs-city && EMACSLOADPATH='$LP:' emacs -nw -Q \
     --eval '(progn (require (quote gascity)) (setq server-name \"gce-rv3\") (server-start))'"
# $LP = <beads.el>/lisp:<beads.el>/.eldev/31.1/packages/vui-1.4.0:<worktree>/lisp
```

Keys were driven with `execute-kbd-macro` against the real buffer, so the
mode keymaps are what is exercised; state was read back with bounded
`emacsclient --eval`. Because `emacsclient` sets `default-directory` to the
client's directory, every eval binds it to the city (or the TRAMP name).

The live run is the workflow that produced this work: `ga-hsbfs`
`build-basic`, `in_progress`, stage `Review` with the fix loop running
(`apply-review-findings ga-qizrn`). **No workflow was mutated:** no retry,
sling, close, cancel, restart, suspend or wake was issued, and the only store
writes in this pass are this bead's own bookkeeping. The live views did
receive the workflow's own events (the stream is attached, `● live`).
