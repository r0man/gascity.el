## Remaining Risks

- **Images depend on the unmerged batch.** The six committed images were
  captured from an integration tree containing W1--W5 (a merged view),
  not from this branch's own `lisp/`.  Until those branches are merged,
  a capture run from this branch alone would produce the old cockpit and
  run-detail renders, and `--verify` here has nothing to compare.  The
  capture is reproducible: the same merge set yields the same bytes.
- **Cold-start capture race.** The very first plain capture in a fresh
  shell/state produced a shorter, partially loaded cockpit image; every
  subsequent capture (and `--verify` from a fresh fixture) produced the
  stable bytes now committed.  The committed images are the verified
  ones, but the pipeline's first-invocation behaviour is worth a
  follow-up bead; regenerating screenshots right after a fresh clone
  should be double-checked against `--verify`.
- **No automated manual/code consistency test.** The AC-2 line is pinned
  by the ERT test in `lisp/test/gascity-runs-test.el` (W2) and copied
  verbatim here; the manual copy is guarded by the recorded diff above,
  not by a committed test.  A future change to
  `gascity-runs--facts-columns` must update the manual, the test and this
  example together; drift would be caught by review, not by `make
  check`.
- **`runs-dark` shows no facts line.** The fixture's Runs view has no
  history row and no failed card, so the regenerated image is
  byte-identical to the old one and the docs cannot show the new
  budgeting there.  The manual's example carries that evidence instead;
  changing the fixture to render a failed/history row would be a
  separate screenshot-contract change, not part of this item.
- The NEWS entry references the absorbed batch beads (ga-shl0s,
  ga-v67dq, ga-wjlx6, ga-th2e2, ga-vinoi), not the implementation beads of
  this drain (ga-f7nvv, ga-40i2t, ga-lya6t, ga-i83g4, ga-4odv8), matching
  how the requirements' out-of-scope section names the batch.
